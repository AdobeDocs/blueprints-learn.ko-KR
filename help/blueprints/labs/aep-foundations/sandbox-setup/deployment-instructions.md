# 배포 지침

> [!NOTE]
>
>자신의 속도에 맞게 실습을 진행하는 경우에만 필요합니다. 라이브 교육 과정 또는 이벤트에 있는 경우 샌드박스가 이미 배포되었습니다.

AEP Foundations 랩 팩은 랩 전체에서 사용할 스키마, 데이터 세트, 데이터 흐름 및 샘플 데이터를 만드는 명령줄 도구인 DEP CLI를 사용하여 샌드박스에 배포됩니다.

## 배포되는 항목

- 4개의 id 네임스페이스
- 1개의 스키마 클래스, 13개의 필드 그룹, 10개의 스키마
- 12 id 설명자, 6 관계/참조 설명자, 3 개의 친숙한 이름 설명자
- 카탈로그 데이터 세트 10개
- HTTP API 소스 연결 1개 및 데이터 흐름 10개
- 프로필 데이터: 단일 디바이스 모드 프로필(3개의 트레이트 데이터 세트, 7개의 이벤트 데이터 세트)과 3개의 조회 데이터 세트
- 2개의 프로필 병합 정책 및 1개의 대상(모든 이벤트 스트리밍, 1시간 이내)

>[!NOTE]
>
>엔드 투 엔드 배포에는 약 2시간 24분이 소요되며, 대부분 단계 간 무인 대기 시간입니다. CLI는 이러한 대기를 자동으로 실행하므로 시간을 직접 조정하지 않아도 됩니다.

## 필요 조건

- **라이선스 권한.** Real-Time CDP을 사용하는 IMS 조직에 대한 관리 권한(스트리밍 세분화 포함)
- **액세스 권한.** [Developer Console 설정](developer-console-setup.md)에서 만든 API 자격 증명을 포함하여 대상 샌드박스에 대한 모든 권한이 있는 Adobe Experience Platform 역할입니다.
- **Developer Console 자격 증명** Adobe Experience Platform API를 포함하는 프로젝트. 아직 없으면 먼저 [Developer Console 설치](developer-console-setup.md)를 따르십시오
- **샌드박스.** 배포를 시작하기 전에 최소 60분 동안 `dev` 유형의 비어 있고 &quot;준비&quot; 상태입니다.
- **Node.js.** Windows 또는 Mac의 모든 최신 LTS 버전

## &#x200B;1. CLI 설치

1. [dep-cli 저장소 복제 또는 다운로드](https://github.com/adobe/dep-cli)
1. `dep-cli` 디렉터리에서 `npm install` 실행
1. `npm start`(으)로 CLI 시작

>[!NOTE]
>
>위의 명령을 실행하려면 Node.js가 필요합니다. Node.js가 아직 설치되지 않은 경우 Wiki의 [Node.js 설정](https://github.com/adobe/dep-cli/wiki/Nodejs-Setup)페이지를 먼저 참조하십시오. 스크린샷과 기존 설치를 업데이트하는 방법을 포함한 전체 설치 세부 정보는 [설치](https://github.com/adobe/dep-cli/wiki/Installation)wiki 페이지를 참조하십시오

## &#x200B;2. 환경 파일 구성

CLI는 환경 파일이 가리키는 샌드박스에 배포되므로 이를 올바르게 설정한 후 실행해야 합니다.

1. `envFiles/sample-env.json`을(를) 복사하고 새 이름을 지정하십시오(예: `my-env.json`).
2. 파일을 열고 [Developer Console 설치](developer-console-setup.md)의 값을 사용하여 다음 필드를 채웁니다.

| **필드** | **값** |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `API_KEY` | 클라이언트 ID |
| `CLIENT_SECRET` | 클라이언트 암호 |
| `IMS_ORG` | 조직 ID |
| `SCOPES` | Experience Platform API 범위(openid, session, AdobeID, read_organizations, additional_info.projectedProductContext)가 포함되어야 합니다. |
| `SANDBOX_NAME` | 타깃팅하는 샌드박스는 비어 있고 유형이 `dev`이어야 합니다. |

3. 파일 저장 및 닫기

>[!NOTE]
>
>CLI 명령을 실행할 때마다 이 파일의 이름을 입력하라는 메시지가 표시되므로 아래 단계에서 다시 사용할 수 있습니다.

## &#x200B;3. AEP Foundations 메뉴 실행

메인 메뉴에서 **AEP 기본 설정**&#x200B;을 선택합니다. 세 단계가 있고 순서대로 진행해야 합니다.

>[!WARNING]
>
>1단계를 실행하기 전에 샌드박스가 최소 60분 동안 &quot;준비&quot; 상태에 있어야 합니다.

| **단계** | **기능** | **실행하기 전에** |
| ----------------------- | ------------------------------------------------------------------------------------------ | ------------------------------- |
| &#x200B;1. 프로필 기반 만들기 | ID 네임스페이스, 스키마, 데이터 세트, 병합 정책 및 대상자 배포 | 샌드박스 &quot;준비&quot; - 60분 이상 |
| &#x200B;2. 프로필 데이터 로드 | 데이터 흐름을 만들고 프로필 및 조회 데이터 스트리밍 | 1단계 후 60분 이상 대기 |
| &#x200B;3. 프로필 상태 확인 | 모든 데이터가 올바르게 로드되었는지 확인합니다. | 2단계 후 15분 이상 대기 |

1단계는 실행하는 데 약 2분, 2단계는 약 6분이 소요되며, 3단계는 자체 기다림 없이 빠른 유효성 검사입니다. 단계 간의 60분과 15분 간격은 AEP이 백그라운드에서 데이터 전달을 완료하는 데 사용됩니다. 이 작업은 2시간 타임라인의 대부분을 차지합니다.

> [!NOTE]
>
>CLI는 이러한 대기 시간을 자동으로 확인합니다. 한 단계를 너무 일찍 실행하면, 몇 분이 남았는지 차단하고 알려줍니다. 시계를 직접 추적할 필요는 없습니다.

>[!NOTE]
>
>2단계는 문제가 발생하면 다시 실행해도 안전합니다. 기존 트레이트 레코드를 덮어쓰고 중복 이벤트는 건너뜁니다.

## 문제 해결

>[!WARNING]
>
>**누락된 이벤트로 상태 검사가 실패합니다**. 일부 프로필 데이터의 전파가 아직 완료되지 않았습니다. 15분 더 기다린 후 프로필 상태 확인 을 다시 실행합니다. 그래도 실패하는 경우 프로필 데이터 로드 를 다시 실행하고 15분 정도 기다린 후 다시 확인합니다.

**다른 오류가 발생했습니다.** 마지막으로, CLI의 샌드박스 관리 메뉴에서 샌드박스를 재설정하고 1단계에서 재배포할 수 있습니다.

>[!CAUTION]
>
>샌드박스를 재설정하면 문제가 해결됩니다. 계속하기 전에 CLI에서 확인할 샌드박스 이름을 입력하라는 메시지가 표시됩니다.
