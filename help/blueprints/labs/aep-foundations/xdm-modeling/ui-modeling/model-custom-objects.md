# 사용자 지정 개체 모델링

## 사용자 정의 필드 추가

강의에서 설명한 대로 고객 계정 사용자 정의 필드를 모델링하는 표준 기본 제공 필드 그룹 또는 데이터 유형은 없습니다.  아래 필드는 현재 사용자 정의로 간주되며 XDM 스키마 내에서 모델링해야 합니다.

- \_\&lt;tenant-name>.account.createDate
- \_\&lt;tenant-name>.account.endDate
- \_\&lt;tenant-name>.account.acqSource
- \_\&lt;tenant-name>.plan.planID
- \_\&lt;tenant-name>.plan.name
- \_\&lt;tenant-name>.customerID

>[!NOTE]
>
>\&lt;tenant-name>은 작업 중인 환경에 따라 다릅니다.



## 계정 개체 작성

1. 스키마 상단에 있는 **+ (추가)** 단추를 클릭하여 새 필드를 추가합니다.

   ![사용자 지정 필드를 추가하려면 스키마 맨 위에 있는 (+) 추가 단추](assets/model-custom-objects-add-a-custom-field-to-your-schema.png)

   >[!NOTE]
   >
   >오른쪽 레일이 열리면 몇 가지 필드를 작성할 수 있습니다



1. 아래 세부 정보를 활용하여 계정 개체를 만듭니다. 완료되면 오른쪽 레일의 **적용** 단추를 클릭하여 스키마 작업 영역의 변경 내용을 확인합니다

| 필드 이름 | 표시 이름 | 유형 | 새 필드 그룹에 할당 |
| ---------- | ------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| *계정* | *계정* | *개체* | *고객 계정 세부 정보 - \[이니셜]*<br />*(여기에 입력하고 드롭다운을 선택하거나 enter 키를 누르십시오.)* |

>[!WARNING]
>
>필드 이름은 특정 대/소문자를 따라야 합니다. 그 이유는 빌드하고 있는 것과 동일한 스키마를 이미 사전 만들었기 때문입니다. 대/소문자가 꺼져 있으면 샌드박스에 있는 기존 스키마의 필드 경로와 충돌이 발생합니다

![할당된 필드 그룹으로 계정 개체 추가](assets/model-custom-objects-adding-the-account-object.png "계정 개체 추가")

>[!NOTE]
>
>자동으로 만든 사용자 지정 필드가 스크린샷에 `_devbc`(으)로 표시된 테넌트 네임스페이스에 배치됩니다. 테넌트 네임스페이스가 다를 수 있습니다. 테넌트 네임스페이스는 사용자 정의 개체를 Adobe 표준 네임스페이스와 구별하고, 향후 Adobe 표준에 대한 추가/업데이트가 사용자 정의 생성 네임스페이스와 충돌하지 않도록 하는 데 사용됩니다.

>[!NOTE]
>
>새 사용자 지정 필드 그룹이 `Field groups` 아래의 왼쪽 레일에 잠금 아이콘 없이 나타납니다.  이는 사용자 정의 작성 필드 그룹임을 나타냅니다.

>[!WARNING]
>
>지금은 스키마를 저장할 수 없습니다. 이 경우 내용이 설명되지 않으므로 JSON 스키마에 빈 개체를 만들 수 없으므로 오류가 발생합니다




1. 방금 만든 계정 개체 아래에 표시되는 다음 필드를 추가합니다.

   | 필드 이름 | 표시 이름 | 유형 |
   | ------------ | ------------- | ---------- |
   | *createDate* | *만든 날짜* | *DateTime* |
   | *endDate* | *종료 날짜* | *DateTime* |

   >[!NOTE]
   >
   >새 필드를 추가하는 동안 **할당 대상** 옵션이 이미 채워져 있고 계정 개체에 사용한 필드 그룹을 참조합니다.



1. 완료되면 스키마 계정 개체는 다음과 같아야 합니다. 스키마를 **저장**&#x200B;합니다!



   ![계정 개체 및 하위 필드가 추가된 고객 계정 스키마](assets/model-custom-objects-account-object-with-child-fields.png)



1. 계정 개체에 사용자 정의 필드를 하나 더 추가합니다. 계정 개체 옆에 있는 **+(추가)** 단추를 클릭합니다.  다음 필드를 만듭니다.

   | 필드 이름 | 표시 이름 | 유형 | 열거 |
   | ----------- | ----------------- | -------- | --------------------------------------- |
   | *acqSource* | *Source 획득* | *문자열* | *웹 :: 웹&#x200B;*<br />*매장 :: 매장* |

   이 필드에는 표준화된 값이 필요하므로 필드 속성 내에서 **열거형 및 제안 값** 옵션을 사용하십시오. 수집 시 이 필드에 대한 유효성 검사와 친숙한 레이블을 추가하려면 **Enum** 라디오 단추를 선택하십시오. 아래와 같이 열거형 값을 추가합니다.

   - *웹 :: 웹*
   - *inStore :: 스토어에서*



   ![획득 Source 필드에 대해 추가된 Enum 값 웹 및 inStore](assets/model-custom-objects-enum-values-for-acquisition-source-field.png)

   >[!NOTE]
   >
   >열거형 및 제안 값의 목표는 최종 사용자가 보다 쉽게 세분화할 수 있도록 하는 것입니다. 열거형은 데이터 수집 시 유효성 검사를 시행하지만 제안된 값은 시행하지 않습니다. 이 기능에 대해 자세히 알아보려면 여기 -> [https://experienceleague.adobe.com/docs/experience-platform/xdm/ui/fields/enum.html?lang=en#enums-and-suggested-values](https://experienceleague.adobe.com/docs/experience-platform/xdm/ui/fields/enum.html?lang=en#enums-and-suggested-values) 설명서에서 자세히 읽어보십시오.



1. 완료되면 **적용** 단추를 클릭하여 스키마에 새 필드를 추가합니다.

1. 스키마 **저장**

>[!TIP]
>
>XDM 스키마 레지스트리 내에 첫 번째 사용자 지정 개체 및 필드를 성공적으로 만들었습니다!



## 계획 객체 작성

위에서 수행한 단계를 반복하고 **계획** 개체 및 관련 필드를 추가합니다. 모든 새 필드는 고객 계정 세부 사항 - \[이니셜] 필드 그룹에 추가해야 합니다.

아래 표의 메타데이터를 사용하여 계획 객체 및 관련 필드를 생성합니다.

| 필드 이름 | 표시 이름 | 유형 | 열거형 및 제안된 값 |
| ---------- | -------------- | -------- | ------------------------------------------------------------------------------------- |
| *계획* | *플랜 세부 정보* | *개체* | - |
| *planID* | *플랜 ID* | *문자열* | - |
| *이름* | *플랜 이름* | *문자열* | 열거형 <br />*기본 :: 기본&#x200B;*<br />*ultimate :: Ultimate *<br />*pro :: Pro* |
| *유형* | *유형* | *문자열* | - |

>[!WARNING]
>
>만든 새 필드를 고객 계정 세부 정보 - \[이니셜] 필드 그룹에 추가해야 합니다.  사용자 정의 필드를 추가하기 전에 왼쪽 레일에서 필드 그룹을 선택하면 필드 그룹이 해당 필드 그룹에 자동으로 추가됩니다.
>
>
>
>![새 필드를 추가하기 전에 왼쪽 레일에서 선택한 고객 계정 세부 정보 필드 그룹](assets/model-custom-objects-field-group-selected-before-adding-field.png)
>
>



완료되면 스키마가 아래 스크린샷과 일치하는지 확인합니다. **스키마를 저장**&#x200B;하세요.



![계획 개체 및 하위 필드가 추가된 고객 계정 스키마](assets/model-custom-objects-plan-object-with-child-fields.png)

>[!TIP]
>
>좋네!  사용자 지정 개체 및 필드를 아무런 도움 없이 추가했습니다!



## 고객 ID 필드 만들기

**customerID** 필드를 이 필드로 추가하는 것은 데이터를 보유할 일반 필드뿐만 아니라 스키마의 기본 ID로 사용되므로 매우 중요합니다.

이전에 수행한 것과 동일한 단계를 수행하고 아래 표를 활용하여 필드에 대한 메타데이터를 참조합니다.

| 필드 이름 | 표시 이름 | 유형 | 필드 그룹 |
| ------------ | ------------- | -------- | --------------------------------------------- |
| *customerID* | *고객 ID* | *문자열* | *고객 계정 세부 정보 - \[이니셜]* |

>[!NOTE]
>
>계층 구조 관점에서 `customerID`을(를) 스키마의 아무 곳에나 넣을 수 있습니다. 이 실습에서는 루트를 유지하고 이전에 만든 사용자 지정 개체 중 하나에 중첩하지 않도록 선택했습니다.  데이터 아키텍처에 의견이 있는 부분입니다
>
>😄



최종 결과는 완료되면 아래 스크린샷과 같아야 합니다

![customerID 필드가 있는 고객 계정 스키마가 루트에 추가됨](assets/model-custom-objects-customerid-field-added.png)
